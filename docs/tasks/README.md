## T2-scanner — жизненная стадия из AAFCO-утверждения

**Читать вместе с** `Ingredients.help/docs/tasks/T2-life-stage.md`. Там
полный контекст и часть приложения; здесь — что делать в этом репозитории.

### Отправная точка (проверено по коду)

1. Фраза **уже извлекается дословно**: `feeding_statement` в
   `lib/extract.ts` (~строка 124), модели прямо сказано копировать её verbatim.
2. Из неё выводится только роль: `detectNutritionRole` в
   `app/api/process/route.ts:380-382`.
3. **Сама фраза не сохраняется.** В `rows` уходит `nutrition_role`, а
   `feeding_statement` выбрасывается. То есть данные уже в кадре, уже
   прочитаны и потеряны — переснимать пачки не нужно.

### Что сделать

- [ ] **Новый модуль `lib/life-stage.ts`** — чистая функция «фраза →
      жизненная стадия»: `growth` / `maintenance` / `all` / `reproduction` /
      `unknown` (фраза есть, стадия не читается) и отдельно `null` (фразы
      нет). Плюс флаг крупных пород — формулировка
      «including growth of large size dogs (70 lbs or more as an adult)»
      меняет смысл и должна выживать отдельным полем.
- [ ] **Побайтная копия** этого модуля в приложении. Файл попадает в список
      «Four things must agree across the two repos» в обоих README — их
      станет пять. Добавить тест сравнения по образцу того, что уже сделан
      для `lib/barcode.ts`.
- [ ] **Писать `feeding_statement` и `life_stage`** в `app/api/process/route.ts`
      рядом с `nutrition_role`. Обязательно провести новые колонки через
      существующий механизм `withoutColumns` (~строка 432): если миграция в
      приложении ещё не применена, запись обязана пройти без этих колонок, а
      не упасть. Приём здесь уже отработан — повторить, не изобретать.
- [ ] **Тесты на реальных формулировках.** Брать их из уже собранного:
      `research/deep-research-*.json` и `data/known-formulas.ts`. Минимум по
      одной фразе от Hill's, Royal Canin, Purina, Blue Buffalo, Weruva —
      они формулируют по-разному, и именно на этом разнообразии парсер
      ломается.
- [ ] `npm run typecheck && npm test && npm run lint` зелёные.

### Чего НЕ делать

- **Не выводить стадию из состава.** Это прямо задокументировано в
  `Ingredients.help/supabase/migrations/0024_nutrition_role.sql`: утверждение о
  кормлении не выводится из списка ингредиентов. Читается из фразы или не
  читается.
- **Не угадывать по названию пачки.** Название читает `dietary-intent` на
  стороне приложения, и это отдельный сигнал. Расхождение между названием и
  утверждением — то, ради чего задача существует; слив их в одно поле это
  расхождение уничтожает.
- **Не добавлять миграцию сюда.** Схема живёт в репозитории приложения, и
  колонки добавляются там (`0026_life_stage.sql`), иначе два репозитория
  разойдутся в том, что такое строка.
