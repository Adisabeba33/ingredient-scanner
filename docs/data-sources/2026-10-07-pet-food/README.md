# Где массово брать штрихкоды и данные кормов
Дата проверки: 7 октября 2026 года. Основной рынок: США и Канада, исходя из текущего проекта ingredient-scanner. Открытая выгрузка ниже — мировая.

## Решение

Для максимального покрытия нужны три независимых слоя: **каталог товаров и фасовок → UPC/GTIN → подтверждённая этикетка и рецептура**. Один поставщик редко хорошо покрывает все три. Приоритет — получить каталоги дистрибьюторов и производителей, дополнить их реестрами зарегистрированных кормов, а состав и показатели брать из этикеток. Платные базы стоит оценивать на пересечении с уже собранными данными.

Подтверждённой общедоступной базы «все бренды, все фасовки, актуальный полный состав» в ходе проверки не найдено. Это не означает, что массового сбора нет: ниже есть работающая открытая выгрузка, проверенный публичный реестр и конкретные каналы получения больших наборов.

Начальные 172 бренда в проекте — рабочий список, а не установленная граница рынка. Полноту следует считать отдельно по брендам, рецептурам, розничным фасовкам и подтверждённым этикеткам. Наличие записей по бренду само по себе не доказывает его полное покрытие.

Я скачал официальный снимок Open Pet Food Facts и выполнил воспроизводимый аудит. Также проверил публичный запрос реестра штата Вашингтон на примере Fromm. Покупки, запросы по электронной почте и изменения production-базы не выполнялись.

## Источники, с которых стоит начинать

### 1. Open Pet Food Facts — можно скачать прямо сейчас

[Раздел выгрузок](https://world.openpetfoodfacts.org/data) · [JSONL.gz](https://static.openpetfoodfacts.org/data/openpetfoodfacts-products.jsonl.gz) · [документация для pet food](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/scanning-cosmetics-pet-food-and-other-products/)

Доступны коды, названия, бренды, масса/количество, категории, страны, тексты состава и метаданные фото. Поля заполнены неодинаково. Есть API и полная выгрузка: для старта выгоднее один раз обработать выгрузку. Коды и страна из сообщества требуют проверки. Условия: ODbL 1.0 для базы, DbCL 1.0 для отдельных данных, CC BY-SA 3.0 для изображений. Условия и атрибуция описаны в DATA-NOTICE.md.

Практическая роль: бесплатный исходный слой, поиск неизвестных брендов и очередь этикеток для OCR. Существующие данные проекта нельзя автоматически заменять этими записями.

### 2. PetWholesaleUSA — подтверждённая схема массового товарного файла

[Официальное описание Product Data](https://www.petwholesaleusa.com/pages/product-data.html)

В опубликованной схеме есть UPC, GTIN, бренд, название, размер, количество, описание, ссылки на изображения и карточку. Активным одобренным клиентам предусмотрены месячный Excel-каталог и обновления остатков по рабочим дням.

Подтверждены формат и поля; сам файл не получен. Не установлено, сколько именно кошачьего и собачьего корма входит в ассортимент и насколько полно покрыты ингредиенты. Первым запросом должен быть образец food-only выгрузки и условия использования данных в приложении-сканере. Обычный доступ розничного покупателя не означает автоматически лицензию на повторное распространение базы.

### 3. WholesalePet.com — выгрузки по выбранным категориям и поставщикам

[Официальная инструкция](https://wholesalepetcom.zendesk.com/hc/en-us/articles/39144589990419-Can-I-Download-Product-Data-and-Price-Lists-on-WholesalePet-com)

Есть выгрузки карточек с SKU, UPC, описаниями и сведениями поставщика. Поддержка готовит массовые выборки по нужным категориям и производителям. Единого самостоятельного скачивания всей базы на странице не обещают.

Следующий конкретный запрос: собачий и кошачий корм, лакомства отдельно, все доступные фасовки; UPC/GTIN, размер, упаковочная иерархия, картинки этикеток, дата изменения, статус товара. Контакт: service@wholesalepet.com. Объём и право использования нужно подтвердить образцом и условиями.

### 4. Северная Каролина — реестр плюс копии этикеток

[Действующая инструкция регистрации кормов](https://www.ncagr.gov/fdfr-existing-firm-new-product-registration-instructions/download?attachment=)

Это наиболее интересная нетривиальная зацепка. Инструкция предусматривает необязательное поле UPC с несколькими кодами через запятую для одного продукта, а также представление копий этикеток. Поэтому ведомство потенциально располагает связкой «продукт → несколько упаковок/кодов → этикетки».

Запросить следует доступную для раскрытия выгрузку CSV/XLSX и электронные копии этикеток: регистрационный ID, компания, бренд, продукт, UPC, тип/вид животного, статус и даты, имена связанных файлов. Контакт: ncfeed.registration@ncagr.gov.

Выгрузка ещё не получена. UPC необязателен; право раскрытия, полнота, доступность массового экспорта, стоимость и сроки неизвестны. Это конкретный канал запроса, а не уже открытый архив.

### 5. Вашингтон — независимый список того, какие продукты существуют

[WSDA Product Look Up](https://agr.wa.gov/departments/animals-livestock-and-pets/animal-feed/product-look-up) · [проверенный публичный запрос Fromm](https://agr.wa.gov/LookupTypes/GetPetFoodList?productName=&companyName=Fromm)

На сайте есть поиск и выгрузка результатов в таблицу. Проверенный запрос вернул 319 строк: название, компания, ID, статус, цикл и даты регистрации. В этом ответе нет UPC и ингредиентов. Возможны повторения названий и разные регистрационные записи.

Практическая роль: расширять перечень брендов и рецептур, находить пропуски в собственном каталоге. Для целого реестра лучше запросить готовый массовый экспорт. Регистрация сама по себе не доказывает наличие товара на полке сегодня.

### 6. Производители — item master и библиотеки этикеток

[Petcurean: ресурсы для североамериканских продавцов](https://petcurean.com/en-us/north-american-retailers) ведут в [библиотеку Plytix](https://ecatalogs.plytix.com/6511f8b8d866e117e5dac95d/file_overview). Сама ссылка подтверждена; конкретный набор полей и массовая выгрузка библиотеки не проверены.

[Fromm Nutrition Guide](https://pos.frommfamily.com/learn/articles/products/nutrition-guide) и [официальный каталог осени 2026](https://shop.frommfamily.com/products/fromm-family-pet-food-catalog-fall-2026) — дополнительные источники для сопоставления рецептур. Нельзя заранее считать потребительский PDF полным справочником UPC.

У каждого производителя искать или запрашивать **item master / product data feed / retail assortment / UPC list / label artwork / guaranteed analysis / calorie content**. Запрашивать данные сразу на все принадлежащие ему бренды. Одна корпоративная выгрузка может закрыть несколько брендов и все их фасовки.

| [Go-UPC](https://go-upc.com/) | API и массовое обогащение списка уже известных кодов; [составы поддерживаются, когда доступны](https://go-upc.com/blog/ingredients-are-live) | Не подтверждена выгрузка всей категории без исходного списка UPC; полнота состава и права хранения |

Показатели KibbleLab — заявления поставщика, а не независимый аудит. Публично проверенного числа UPC на отдельные упаковки и цен на весь набор нет. NIQ/Syndigo также нельзя оценивать по их общим маркетинговым объёмам всех товарных категорий.

Перед оплатой нужен один одинаковый тестовый образец: 100–200 записей, включая новые для проекта бренды, несколько фасовок одной рецептуры, multipack, снятый с продажи товар и обновлённую рецептуру. Сравнивать **стоимость нового подтверждённого розничного GTIN**, а не стоимость строки или рекламный размер базы.

В договоре или коммерческом предложении уточнять хранение после окончания подписки, показ пользователям приложения, хранение оригинальных фото, распознавание и производные данные, передачу подрядчикам, лимиты и обновления. Доступность страницы или API не означает все эти права.

## Дополнительные каналы для закрытия пробелов

- **Страницы сетевых магазинов.** Проверенная [карточка ShopRite Freshpet 1 lb](https://www.shoprite.com/sm/pickup/rsid/106/product/freshpet-homestyle-creations-grilled-chicken-bites-freshly-crafted-meals-dog-food-1-lb-id-00627975013387) содержит UPC 00627975013387, фасовку, ингредиенты и указание пищевой полноценности. Это доказательство полезности конкретного источника, не обещание полного открытого фида. Для регулярного сбора нужен подходящий доступ и соблюдение ограничений сайта.
- **Планограммы магазинов.** В [публичном PDF DeCA за апрель 2026](https://corp.commissaries.com/media/9774) есть товары, бренды, размеры и столбец UPC. Некоторые идентификаторы используют формат сети, в том числе могут не содержать контрольную цифру. Хранить исходное значение и подтверждать соответствие точной упаковке; не дополнять цифры наугад.
- **Каталоги дистрибьюторов прошлых лет.** [ADMC](https://www.admc.us/products/product-catalogs/) прямо указывает дату 16 июня 2023 и предупреждает о возможных неточных UPC. Пригодны для поиска кандидатов; для актуального каталога нужен новый price book.
- **GS1.** [Verified by GS1](https://support.gs1.org/support/solutions/articles/43000734119-what-information-is-available-in-verified-by-gs1-) помогает проверять идентификатор, компанию и базовые сведения. Это не подтверждённый источник полного состава всех кормов.

Не стоит перебирать возможные UPC по префиксам: корректная контрольная цифра не подтверждает существование товара. Штрихкод производителя, номер магазина и номер коробки нельзя смешивать.

## Как поставить сбор на производство

### Единица хранения

| Сущность | Основные поля |
|---|---|
| Рецептура и её версия | Бренд/производитель, линейка, рецепт, вид животного, возраст, форма корма, рынок, период актуальности |
| Розничная упаковка | UPC/EAN как строка, нормализованный GTIN, вес/объём, количество единиц, тип упаковки, одиночная единица или multipack |
| Логистическая упаковка | Код коробки, количество розничных единиц, связь с их GTIN; отдельный barcode_scope |
| Состав и показатели | Полный исходный текст и язык, нормализованные ингредиенты, guaranteed analysis с единицами и min/max, калории и их база, AAFCO/adequacy |
| Наблюдение источника | URL или имя файла и лист/строка, дата получения, дата источника, hash, лицензия/права, оригинал этикетки, способ извлечения и статус проверки |

Дополнительные поля, когда источник их даёт: кормление, предупреждения, аллергены/маркетинговые заявления, страна производства, статус продажи, цена и доступность с привязкой к магазину и времени. Не выводить отсутствующие нутриенты из рекламы или отдельных ингредиентов.

Одна рецептура может иметь много фасовок и кодов. Один код может со временем сопровождать изменившуюся этикетку. Поэтому состав нужно версионировать; нельзя один раз навечно приклеить текст к UPC.

### Очередь обработки

1. **Обнаружение ассортимента.** Объединить текущий seed, реестры, каталоги производителей и дистрибьюторов. Сохранить рынок и дату. Не ограничивать поиск известными 172 брендами.
2. **Коды и фасовки.** Сначала обработать доступные массовые файлы. Сохранить ведущие нули, проверить контрольную цифру и упаковочную иерархию. Сопоставить по точному товару и размеру. Не чинить ошибочный код догадкой.
3. **Обогащение рецептуры.** Присоединить страницу производителя, этикетку, ингредиенты, GA, калории и adequacy. Одну проверенную рецептуру использовать для разных размеров лишь при подтверждённом совпадении версии и рынка.
4. **Распознавание пробелов.** OCR только этикеток, для которых нет качественного текста. Сохранять исходную картинку и извлечение. Модель может структурировать прочитанное; недостающие цифры, ингредиенты и штрихкоды оставлять пустыми.
5. **Контроль качества и публикация.** Проверить против всех существующих реестров проекта, включая wrong-barcodes и multipacks. Неустранённые конфликты оставлять в очереди кандидатов. В production переносить только записи с достаточными доказательствами.
6. **Обновления.** Для начала — полный снимок доступного каталога; затем сравнение дат/хешей и изменившихся записей. Частоту согласовать с реальной частотой обновления источника: недельный каталог не нужно перечитывать каждые пять минут.

Для источников с запрещённым или недоступным автоматическим сбором использовать разрешённую выгрузку, лицензированный фид или запрос владельцу. Авторизованные кабинеты не обходить.

### Что использовать из текущего проекта

В ingredient-scanner уже есть разделение продуктов, формул, multipacks и ошибочных кодов, а также research-ledgers. Полезно сохранить эту модель.

- `scripts/brand-inventory.mjs`: оценивать существующее покрытие и выбирать пробелы.
- `scripts/formula-worklist.mjs`: организовывать сбор на уровне рецептур.
- `scripts/harvest-maker-pages.mjs`: переиспользовать существующий сборщик страниц для поддержанных производителей.
- `scripts/check-ledger.mjs`: проверять подготовленные research-записи перед отдельным переносом в основные данные.

Найденный внешний источник — ещё не source_verified. Для любой записи остаются обязательными точное соответствие товара/фасовки, подтверждение состава, корректный barcode_scope и проверка дублей. В рамках этого исследования файлы репозитория не менялись.

### Порядок запуска

1. Сравнить приложенные 234 кандидата США/Канады с текущими данными; отдельно разметить остальные североамериканские записи полного снимка.
2. Получить массовый список WSDA; направить конкретный запрос Северной Каролине на реестр и доступные этикетки.
3. Запросить образцы у WholesalePet и PetWholesaleUSA и item master у нескольких крупных производителей.
4. Если бюджет допускает, сравнить образцы KibbleLab и NIQ/Syndigo на новых GTIN и полноте этикеток. Barcode Lookup рассматривать с учётом условий удаления, Go-UPC — как обогащение известных кодов.
5. Подключать по одному адаптеру источника, сохраняя сырой снимок, наблюдения, конфликты и отчёт о приросте. OCR запускать после объединения текстовых источников.
6. Показывать отчёт: новые уникальные розничные GTIN; новые рецептуры; доля точных фасовок; доля полных составов; GA/калории; подтверждённая свежесть; дубли; конфликты; стоимость одного полезного дополнения.

Это план внедрения. Готовый код в приложении реализует скачивание и аудит OPFF, а не всю многоканальную систему.

- `sources.json` — 16 источников, подтверждённые поля, доступ и ограничения.
- `audit_opff.py` — воспроизводимый сбор и аудит официальной выгрузки; Python 3.10+, без сторонних пакетов.
- `data/openpetfoodfacts-products-2026-10-07.jsonl.gz` — полный исходный снимок.
- `data/opff-audit.json` — точные счётчики, фильтры и контрольная сумма.
- `data/opff-cat-dog-candidates.jsonl` — 2 593 кандидата по всему миру.
- `data/opff-us-ca-cat-dog-candidates.jsonl` — 234 из них с меткой США/Канады.
- `data/wsda-fromm-registration-sample.json` — проверенный ответ WSDA, 319 регистрационных строк.
- `DATA-NOTICE.md` — атрибуция, лицензии и пределы использования.

Повторить аудит сохранённого снимка:

```bash
python audit_opff.py --input data/openpetfoodfacts-products-2026-10-07.jsonl.gz --out rerun --source-last-modified 'Wed, 07 Oct 2026 00:15:57 GMT'
```

Получить новый официальный снимок и обработать его:

```bash
python audit_opff.py --download --out latest --user-agent 'YourApp/1.0 (your-contact-address)'
```

Скрипт сохраняет только кандидатов с явной категорией cat/dog и подходящей контрольной цифрой GTIN. 47 записей с такими категориями не прошли проверку кода. Среди экспортированных кодов 74 восьмизначных; они условно трактуются как GTIN-8, преобразование UPC-E не выполняется. Даже корректная контрольная цифра не доказывает правильное присвоение кода или актуальные продажи.

Кандидаты имеют статус `source_candidate_not_verified`. Они не сверены с вашим репозиторием и не являются 2 593 новыми подтверждёнными добавлениями. Наличие текста не гарантирует полного состава; отсутствие структурированных nutriments не означает отсутствие показателей на фотографии. Изображения не скачивались: в производных файлах сохранены выбранные метаданные и ссылка на исходную карточку.
